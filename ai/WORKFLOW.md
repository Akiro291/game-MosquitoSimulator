# AI Agent Workflow — Mosquito Simulator

## Как агент должен работать

### Шаг 1 — Analyze
Перед задачей:
- Прочитай `ai/CURRENT.md`, `ai/PROGRESS.md`, `ai/GDD.md`, актуальный раздел `ai/PROMPTS.md`
- Найди относящиеся классы в `Source/MosquitoSimulator/`
- Определи, что уже реализовано, а что является заглушкой

### Шаг 2 — Plan
Перед изменениями коротко напиши:
- Что нашёл
- Что собираюсь менять
- Какие файлы затрону
- Как буду проверять

Дождись подтверждения пользователя, если задача не тривиальная.

### Шаг 3 — Implement
Делай минимальное изменение, необходимое для задачи.  
Не переписывай соседние системы без причины.

### Шаг 4 — Verify
- Скомпилируй C++ (редактор должен быть закрыт)
- Предложи headless-проверку (рецепт в PROGRESS.md)
- Проверь Output Log / headless-лог на критические ошибки

### Шаг 5 — Report
Формат ответа:

**Сделано**
- ...

**Файлы**
- ...

**Проверка**
- ...

**Проблемы**
- ...

**Следующий шаг**
- ...

В конце сессии **обязательно** обнови `ai/PROGRESS.md`.

## Если задача слишком большая

Разбей её на последовательность маленьких шагов.  
Плохо: «Сделай всю систему смерти и погони».  
Хорошо: «Сначала добавим Die() и Respawn, потом штрафы крыльев».

## Если агент не уверен

Не угадывай архитектуру.  
Сначала исследуй существующий код.

## Запрещено без необходимости

- Массово переписывать проект
- Удалять рабочий код
- Менять Build.cs без причины
- Создавать дубликаты классов
- Реализовывать механики из 0.2+ до прохождения плейтест-гейта MVP 0.1
- Добавлять сторонние плагины ради простых решений

## Работа с пользователем

Пользователь занимается вайбкодингом.  
Агент должен:
- Сам находить нужные файлы
- Объяснять, что делает
- Не требовать от пользователя писать большие куски кода вручную
- При необходимости давать пошаговые инструкции для Unreal Editor
