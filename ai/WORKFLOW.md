# AI Agent Workflow — Mosquito Simulator

## Как агент должен работать

### Шаг 1 — Analyze

Перед задачей:

- изучить структуру проекта;
- найти относящиеся к задаче классы;
- найти Blueprint;
- проверить существующие системы;
- определить зависимости.

### Шаг 2 — Plan

Перед изменениями кратко написать:

- что найдено;
- что будем менять;
- какие файлы затронем;
- как проверим.

### Шаг 3 — Implement

Делать минимальное изменение, необходимое для задачи.

Не переписывать соседние системы без причины.

### Шаг 4 — Verify

Проверить:

- компиляцию C++;
- Blueprint;
- references;
- runtime behavior;
- ошибки в Output Log, если доступно.

### Шаг 5 — Report

Формат:

**Сделано**
- ...

**Файлы**
- ...

**Проверка**
- ...

**Проблемы**
- ...

**Следующий шаг**
- ...

## Если задача слишком большая

Разбить ее на последовательность.

Плохо:

> Сделай всю систему AI людей.

Хорошо:

1. Найти текущий Human Character.
2. Добавить состояние Calm.
3. Добавить обнаружение комара.
4. Добавить Noticed.
5. Добавить реакцию.
6. Добавить Irritated.
7. Добавить Chase.
8. Протестировать.

## Если агент не уверен

Не угадывать архитектуру.

Сначала исследовать проект.

## Запрещено без необходимости

- массово переписывать проект;
- удалять рабочий код;
- менять Build.cs без причины;
- менять Project Settings без объяснения;
- создавать дубликаты классов;
- добавлять сторонние плагины только ради простого решения;
- реализовывать поздние механики до MVP.

## Работа с пользователем

Пользователь занимается вайбкодингом и не обязан заранее знать правильную Unreal-архитектуру.

Поэтому агент должен:

- объяснять, что делает;
- сам находить подходящие файлы;
- предлагать конкретные действия;
- не требовать от пользователя вручную писать большие объемы кода;
- при необходимости давать пошаговую инструкцию в Unreal Editor.

## Важное ограничение

AI не должен считать запрос пользователя разрешением на любые изменения.

Если задача потенциально разрушительная — сначала объяснить риск и попросить подтверждение.
