# Mosquito Simulator — Architecture Notes

Этот файл является ориентиром, а не приказом создавать все перечисленные классы прямо сейчас.

## Общий принцип

Архитектура должна расти вместе с игрой.

Не создавать 50 классов заранее.

## Предполагаемые основные сущности

### Mosquito Character

Отвечает за:

- движение;
- полет;
- состояние комара;
- взаимодействие с миром.

Возможные данные:

- Health/Survivability;
- Energy;
- Blood;
- Hunger;
- Noise;
- Visibility;
- FlightSpeed;
- WingCondition.

### Human Character

Отвечает за:

- движение;
- взаимодействие;
- реакцию на комара;
- состояние раздражения;
- попытки атаки.

Состояния:

Calm
→ Noticed
→ Irritated
→ Angry
→ Chase

### Mosquito Interaction Component

Общая точка для:

- обнаружения человека;
- посадки;
- укуса;
- получения крови;
- завершения укуса.

### Detection System

В будущем может объединять:

- визуальное обнаружение;
- звук;
- близость;
- CO2;
- тепло;
- запах.

Не реализовывать всю систему сразу.

### Day/Night System

Отвечает за:

- время суток;
- освещение;
- модификаторы активности NPC;
- модификаторы активности комаров.

## AI

Для людей:

- базовое перемещение;
- реакция на комара;
- атака;
- в будущем расписания.

Для хищников:

- отдельные простые поведения.

## Blueprint

Blueprint допустим для:

- настройки NPC;
- настройки объектов;
- VFX/SFX;
- простых реакций;
- прототипов.

## Data Assets / Data Tables

Когда количество типов объектов/персонажей вырастет, параметры лучше выносить из кода.

Примеры:

- HumanTypeData;
- MosquitoEvolutionData;
- EquipmentData;
- PredatorData.

Не создавать эти структуры заранее, если они пока не нужны.

## Save System

Появится на Version 0.2.

Сохранять в первую очередь:

- прогресс;
- очки;
- открытые улучшения;
- состояние линии поколений;
- необходимые настройки.

## Важное правило

Если фактическая архитектура проекта уже отличается от этой документации, сначала анализируй существующую архитектуру.

Документация описывает цель, а не повод ломать текущий код.
