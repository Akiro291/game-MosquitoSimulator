# MosquitoSimulator — MVP 0.2 Plan

**Base:** commit `17e0f16` "MVP 0.1 collision system stabilized" (чистое дерево, всё MVP 0.1 работает и проверено в PIE).
**Принцип:** MVP 0.2 = один законченный, тестируемый этап: «паук-ловушка + биологическая прогрессия с наследованием между поколениями + минимальный персистентный сейв + расширения существующего Canvas HUD». Никакого UMG, никаких переписываний коллизии/movement/AI/аудио.

## Решение владельца (зафиксировано в этой сессии)

1. **Паутина = Trapped + struggle**: вход в зону сети обездвиживает комара (полёт/движок не трогаем — просто гейтим ввод), шкала побега уменьшается от быстрых нажатий клавиши, паук подходит и бьёт комара во время борьбы. Без физики, импульсов, forced movement.
2. **Паук = Idle + короткая атака (lunge)** в пределах зоны своей сети. Без pathfinding patrol/chase.
3. **Паук killable**: убийство за существующий bite-путь → очки + XP, сеть исчезает.
4. **Прогрессия двухслойная, биологическая** (см. §4). Никакой generic RPG-статистики (Strength/Dex/Int).
5. **HUD остаётся Canvas** (`AMosquitoHUD`), UMG не вводим.
6. **Мягкое наказание смертью**: Respawn — Health/Wings/Energy полные, Blood и Hunger — нет.

## Разрешение противоречий в документации (сделать при старте)

- `ai/CURRENT.md` §«Запрещено сейчас» (spiders/saves/real UI) — снять после начала 0.2 по явному решению владельца (это и есть данное планирование); обновить в Phase 0.
- `ai/HANDOFF.md` NEXT: «P1 паук + простая прокачка за Score» — уточнить: Score **конвертируется в XP**, апгрейды покупаются за level-up points, lifetime Score — витрина рекордов + источник species-очков.

## 1. Паук + паутина (Spider/Web)

### Что получает игрок
Новый хищник-«зона страха»: сеть между деревьями ловит комара, паук бьёт; можно рискнуть и убить паука — получить крупную награду и очистить зону.

### Зачем игре
GDD §14: «паук создаёт зоны страха, не ещё один моб». Второй после человека тип угрозы, мотивирует изучать мир, напрямую кормит XP/прогрессию (kill = крупная награда) и future-proof для 0.3 (хищники, поколения).

### Детальный дизайн (по ТЗ владельца)
- **Где живёт**: одна сеть у дерева `TreeTrunk2 (-800,650)` (северо-западный квадрант) — в стороне от трёх точек спавна людей ((-300,250), (150,550), (500,-200)) и PlayerStart (0,0,120); спавнит GameMode (`bSpawnSpider`), transient, как люди.
- **Взаимодействие**: вход комара в `WebRadius` (~120 см, сфера вокруг центра сети) → `bTrapped`: ввод полёта игнорируется (early-return в колбэках Move*; `Movement->Velocity=0` каждый тик — аналог уже существующего `StickToLandedHuman`-паттерна), обычные keys взлёта НЕ освобождают.
- **Побег (struggle)**: `EscapeMeter` стартует, напр., 1.0; каждое нажатие **R** (новый `IA_Struggle`; при удержании — авто-прирост ×0.3, чтобы не ломать пальцы) −0.12, пассивный decay +0.05/с; при 0 → свобода, `bTrapped=false`, полёт восстанавливается немедленно. Правки MosquitoCharacter — только гейты/раннеры, canonical flight/collision не трогаются.
- **Взаимодействие паук↔комар**: паук Idle на сети; если комар trapped (или в `WebRadius`) → цикл: телепортно-плавный подход на 2–3 шага к комару (только внутри WebRadius) → bite-windup 0.5 с (визуально приседание/наклон меша) → урон **через существующий `ApplySwatHit`** (wing damage + camera kick + flash, без импульса — как у SWAT) → cooldown 2 с. Комар не может кусать/лендиться на людях, пока trapped (`bTrapped` блокирует `OnBitePressed`).
- **Нужна ли AI**: минимальная — 2 состояния внутри Actor Tick (enum `ESpiderState {Idle, Lunge}`), как FSM человека, но без Behavior Tree и без движения наружу из сети.
- **Смерть паука**: 3 успешных укуса, **только когда паук в фазе замаха (windup)** — окно уязвимости; укус = ЛКМ рядом (тот же distance-путь, что посадка). Смерть: actor Destroy, сеть исчезает, `+150 Score/XP`, лог-маркер.
- **Web — физический объект или query?**: **только gameplay-запрос** (дистанция до центра сети, как `NearestHumanDistance`; визуал сети — NoCollision меш-примитивы). Никаких новых collision-каналов/профилей/блоков — collision v5b остаётся нетронутой. Это прямой вывод из истории багов (Block↔Ignore↔Overlap, `DefaultResponse`-ловушка).
- **Визуал/звук**: ноль ассетов — плоские «нити» (тонкие Plane/Cylinder-примитивы) через `MosquitoPaint`, тёмно-серый; жужжаще-щелкающий процедурный one-shot по образцу `MosquitoAudio`; HUD-предупреждение о близости сети.

### Системы/классы/файлы
- Новые: `SpiderCharacter.h/.cpp` (AActor не Character — паук не ходит далеко), `MosquitoAudio` += генератор паука.
- Правки (минимальные): `MosquitoCharacter.h/.cpp` (bTrapped, EscapeMeter, IA_Struggle, гейты вход/укус, смерть/респаун чистят trapped), `GameModeBase.h/.cpp` (спавн), `MosquitoHUD.h/.cpp` (trapped-бар), `Build.cs` — без изменений.

### Риск регрессии MVP 0.1: **Medium-Low**
Точки контакта: input-гейты комара (только ранние выходы), Respawn-очистка. Collision / Human-AI / DayNight / audio не затронуты.
Особые случаи: trapped+landed — взаимно исключаются; trapped+смерть (HP от укусов паука) → Respawn обязан снять trapped **до** EnableInput; trapped при входе человека в сеть — люди сеть игнорируют (пробегают, как игнорируют комара).

### Verification
- **PIE**: влёт в сеть → стоп → частые нажатия R → вылет; паук бьёт во время борьбы, крылья/тряска/флеш работают; 3 укуса в windup → паук и меш сети исчезают, награда; полёт рядом с сетью (вне радиуса) не затронут; landing/bite на человеке не сломаны; человек пробегает сквозь сеть без эффекта; смерть от паука → респаун с полным контролем.
- **Headless** (рецепт PROGRESS.md, `-benchmark -benchmarkseconds`): маркеры `[Spider] Spawn OK`, `Web at ...`, `Blockout village ready`, 3× Human spawn; 0 fatal/ensure; dev-флаг `-SpiderTest`: телепорт игрока в сеть → в логе `TRAPPED` → эмуляция борьбы (debug-хук вызывает `Struggle()` N раз) → `ESCAPED`; `-KillSpider`: 3× вызов `TakeBite()` → `[Spider] Died +reward`.

### Зависимости
Спайдер-ядро не зависит ни от чего. Награда kill-очками → нужна точка lifetime-хранения (§0). HUD-элементы — после самой механики.

## 2. Save (минимальный)

### Что получает игрок
Твои species-улучшения и рекорды переживают закрытие игры.

### Зачем игре
Наследование поколений из главной петли GDD (охота→риск→награда→«размножение») требует персистентности хотя бы в зачатке; без сейва второй слой прогрессии бессмысленен.

### Дизайн
- **Что сохраняем**: species-ветки+уровни, `UnspentSpeciesPoints`, `LifetimeScore`, `BestChaseScore`, `TotalDeaths`, `Generations`, `Version`. **НЕ сохраняем**: статы текущей комарицы, позиции акторов, время суток, run-XP.
- **Когда сохраняем**: покупка species-апгрейда, смерть (после начисления species-очков), `EndPlay` GameInstance (выход из игры/закрытие). Никаких слотов, автосейв-only.
- **Когда загружаем**: `GameInstance::Init()` один раз.
- **Формат**: **config-сейв** — `UCLASS(Config=MosquitoSave)` + `SaveConfig/LoadConfig`, файл по `GetSaveGameSystemFilePath()` (`Config/MosquitoSave.ini`). Минимально возможный «формат данных» без парсеров, без GameUserSettings/SaveGame-подсистем.
- **Дев-хелперы**: флаг `-WipeSave` (удалить файл) + лог `[Save] Loaded version=N species=...` / `[Save] Written` для headless-доказательства.
- Сложную систему (слоты, опции, settings, облако) НЕ делаем.

### Файлы
Новый: `MosquitoSimulatorGameInstance.h/.cpp`. Правки: `GameModeBase.cpp` (+5 строк `GameInstanceClass=...` в ctor), вызовы записи из классов §4. `Build.cs` без изменений.

### Риск: **Low** (чисто additive, единственный shared-класс, который раньше не существовал).
Сценарий падения файла/кривой версии: load с дефолтами, без крэша (проверить, сохранив битый ini вручную).

### Verification
- **PIE**: купить species-апгрейд → закрыть игру → запустить → HUD показывает сохранённый уровень/рекорды.
- **Headless**: run1 пишет (`[Save] Written`, exit 0) → run2 читает (`[Save] Loaded` с теми же значениями) — два лога, автоматически проверяются грепом; run3 с `-WipeSave` → дефолты.

### Зависимости
§0 GameInstance — общий контейнер; после §4 (покупки).

## 3. Simple UI — расширения Canvas HUD (не UMG)

### Что получает игрок
Читаемая обратная связь новых систем: сеть/плен, XP/уровни, панель апгрейдов, персистентные очки.

### Элементы (все — `DrawRect/DrawText` в `AMosquitoHUD`, ноль ассетов)
1. **Web proximity chip** («WEB AHEAD» при <250 см, красная плашка при trapped + горизонтальный `EscapeMeter`-бар по центру экрана).
2. **Run XP/Level** — под Score-плашкой.
3. **Панель апгрейдов** (run: hotkey **Tab**, пауза геймплея НЕ ставится; death: показывается автоматически поверх DEAD-оверлея) — ветки, стоимости, свободные очки, горячие клавиши 1–4.
4. **Species-line + death-panel**: species-очки и покупка species-веток — только на death-screen (ту же клавиатуру 1–4, отдельная секция панели; см. §4).

### Файлы
`MosquitoHUD.h/.cpp` (новые Draw*-функции), getter'ы к §0/§4, `AMosquitoCharacter::IsTrapped()/GetEscapeProgress01()`.

### Риск: **Low**. Существующий HUD не переделывается; регрессия возможна только через null-геттеры новых данных (держать null-guard'ы по образцу `DrawHumanState`).
- **PIE**: бары не перекрывают старые; панель открывается/закрывается, полёт во время панели — намеренно свободен (мигающий текст «panel open»).
- **Headless**: `[MosquitoHUD] First draw` остаётся; тест: дев-клавиша эмулирует toggle — в `-game` без ввода достаточно маркеров данных в логах.

## 4. Progression — два биологических слоя (только foundation)

### Что получает игрок
Ощущение роста: текущую комарицу можно «прокачать» прямо во время забега, а после смерти — вложить наследственные очки в ветки вида; следующие комары сильнее.

### Слой A — Current Mosquito (run)
- **XP-источники**: укус (XP = amount of gained blood), секунды живого полёта (напр. 1 XP/с), секунды в Chase, kill паука (+150). Отдельный `AddXP()` в GameInstance; Score остаётся отдельной валютой рекордов.
- **Кривая**: `xpToNext = 100 * level`; каждая level → **+1 level-up point**.
- **Ветки (по 3 уровня максимум, цена 1 пункт за апгрейд)** — биология комара, не RPG:
  - `WingControl` — манёвренность: +15% MaxAcceleration (канонический `FlightSpeed` НЕ трогаем),
  - `MuscularPropulsion` — +8% `FlightSpeed`-множитель (применяется там же, где существующие wing/exhausted-множители в `UpdateStats`),
  - `WebEscapeReflexes` — +20% урона по `EscapeMeter` за нажатие (сопротивление сети),
  - `Metabolism` — −15% HungerRate.
- **Покупка «в любое время»**: run-очки тратятся хоткеем **Tab** (Canvas-панель, §3), без паузы мира.
- Смерть: всё обнуляется, **новая комарица Level 1**, старт с species-бонусами.

### Слой B — Species / Genetics (persistent)
- **Начисление**: +1 species-очко за каждые ~200 lifetime-очков, начисленных **после смерти** (срабатывает в Respawn-пути: начислить, написать сейв) — «поколение отдало долг виду».
- **Ветки-заготовки** (покупки только на death-screen, тот же Canvas, 2–3 уровня): `BloodEfficiency` (+10% `BloodGainPerBite`-максимум), `WebResistantAdhesion` (пассивно ниже EscapeMeter decay), `Exoskeleton` (+10 MaxHealth). Именованы и структурированы extensibly — будущие mating/partner и «мутации» просто добавляются как новые ветки, без рефакторинга. Mating НЕ реализуем.
- **Хранение**: §0 GameInstance; применение — в `Respawn()` (species-бонусы входят в стартовые Max-значения) и в существующие места применения множителей (`UpdateStats`, read-sites `BloodGainPerBite`).
- **Death punishment-правки** (решение владельца): в `Respawn()` `CurrentBlood = 20` (не Max), `CurrentHunger = 70` (не 0); `Generations++`, `TotalDeaths++`.

### Файлы
Новый: `MosquitoProgressionTypes.h` (структуры run/species data + constexpr costs). Правки: `MosquitoCharacter.cpp` (вызовы AddXP в CompleteBite/Tick; AddScore — добавить forward в GameInstance, ~2 строки; Respawn-секция), §0 GameInstance (данные/CRUD), `MosquitoHUD` (§3 панель). `HumanCharacter.cpp` НЕ трогаем — Chase-скоринг уже льёт Score в комара.
### Риск: **Medium-Low**. Touchpoints: Respawn() — критический путь MVP 0.1 (ввод, телепорт, PlayerStart): менять только значения статов + новые вызовы; `UpdateStats` — только домножить на множители апгрейдов рядом с существующими SpeedMult.
### Verification
- **PIE**: накусать → level-up → Tab-панель → купить WingControl → заметный рост отзывчивости; умереть → death-screen показывает species-очки и новые комарицу Level 1, но с Exoskeleton +health; перезапуск → species сохранился.
- **Headless**: `-StatSpeed=100 -benchmark` до умерщвления (паттерн `[Mosquito] Died` уже есть) → проверить `[Save] Written` со `SpeciesPoints>=1`, `Generations=1`; следующий run → `[Save] Loaded ... Generations=1`.
### Зависимости
Требует §0 (GameInstance). Spider-kill-XP требует §1. UI-панель — §3.

## First Implementation Task

**Phase 1: создать `AMosquitoSimulatorGameInstance` с config-сейвом и назначить его в GameMode.**
Почему первым: это наименее конфликтная и единственная shared-зависимость (сейв §2 и прогрессия §4 не существуют без него, а spider §1 к нему не привязан); additive ~120 строк с нулевым риском для 0.1-систем; и она полностью верифицируется headless за два прогона (write→read) до того, как в проект зайдёт первая новая механика. Механика паука пойдёт второй фазой — как самая видимая игроку фичa, не блокируемая ничем.
